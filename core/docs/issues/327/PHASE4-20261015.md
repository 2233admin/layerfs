## Changes

- The [read-only A6 investigation](A6-INVESTIGATION-20261015.md) traces the
  authenticated control endpoint, private keys, runtime reopening gap, Workspace
  tokens, service Sandbox, process ownership and cross-process close/uncertainty.
  It is research, not a cross-process capability or an A9 PASS.
- Closed R8 registries are unchanged. Their new
  [archive notice](../../../benchmark/cluster-two/registry/README.md) marks
  `shared_processes` references as historical targets that were removed.
- The independent runtime's surviving history/dedup/footprint oracles now set up
  saved candidates with `commit_branch` and current metadata-aware identities.
  Staging behavior is not restored. Old outcome and receipt type references are
  updated in the harness. Its failed checks below remain failures.
- The provenance checker now recognizes the already-authorized patch at the
  relocated passthrough harness manifest/lock. No dependency or third-party
  source changed.
- `new LayerFS(projectName)` captures deployment environment strings with no
  filesystem, addon or network I/O. The README documents the home, Engine socket,
  image, volume, daemon and addon variables.
- `@layerfs/sdk/operator` has its own JS entry point, native `operatorCall`, API
  `operator::call`, and daemon operator dispatch. Currently it implements
  `inspect.snapshot(since?)`, `process.list(sandbox)` and
  `process.cancel(sandbox, process)`. Public dispatch refuses `operator.*`.
  Process control remains in the native executor. Demo and kept verification
  callers use the operator. No product HTTP server is introduced.
- Removed the retired public inspect/process wrappers and the entire harness
  implementation/export. Deleted the old A6 harness test outright, including
  its attribution assertions; the old receipt remains. Surviving ordinary
  mount/exec/Commit behavior still has its independent tests.
- Addon build tooling handles `.dylib` on macOS and `.so` on Linux, uses pinned
  Cargo and worktree-local targets, and supports separate platform output paths.
- Boundary scanning covers SDK/native/operator product files. Entry modules
  delegate to named dispatch files. The LOC counter includes operator sources;
  SDK exclusions use paths relative to the SDK, so a snapshot exported beneath
  a directory named `target` no longer accidentally excludes all SDK source.
